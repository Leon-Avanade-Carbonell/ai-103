## Key concepts and decisions

- **M01-U01 — Iterative lifecycle:** define the problem → get data → prepare data → train → integrate → monitor. Microsoft Learn treats deployment as part of a continuous process, not its end. The tutor's retailer illustration emphasizes comparing predictions with actual outcomes and agreed success criteria before deciding to investigate or retrain. Changed buying habits alone do not prove degradation; possible causes remain hypotheses. [Notes](notes.md#m01-u01--introduction) · [Source](https://learn.microsoft.com/en-us/training/modules/design-machine-learning-model-training-solution/1-introduction)

- **M01-U02 — Output determines the task:** categories → classification; numerical values → regression; future numerical values based on time-series data → forecasting; image analysis → computer vision; text insights → NLP. The task constrains algorithms and metrics. The official workflow is load/inspect → preprocess/clean → split training/test data → configure algorithm → train → score → evaluate. **Training** learns patterns; **scoring** produces predictions; **evaluation** compares them with actual outcomes. [Notes](notes.md#m01-u02--define-the-problem) · [Source](https://learn.microsoft.com/en-us/training/modules/design-machine-learning-model-training-solution/2-identify-tasks)

  **Metric rules from the recorded supporting Azure ML API v2 reference:** precision = correctly flagged positives / all flagged positives; recall = correctly flagged positives / all actual positives; accuracy = correct classifications / all examples; MAE = mean absolute numerical error. Identify the positive class and denominator first, then compare the metric named in the requirement with its threshold. “At least” includes equality; “MAE no greater than $15,000” means ≤ $15,000. [Metric notes](notes.md#match-metrics-to-success-criteria) · [Supporting source](https://learn.microsoft.com/en-us/azure/machine-learning/how-to-understand-automated-ml?view=azureml-api-2)

- **M01-U03 — Prepare the required representation:** identify source, current format, desired training format/serving layer, and ingestion tasks. The official IoT example transforms semi-structured JSON into average temperature per machine per minute: source → Synapse copying/transformation → Blob Storage prepared data → Azure ML training. This is an example architecture, not a universal requirement; Databricks and Azure ML are also named ingestion options. **ETL** transforms before loading; **ELT** loads before transforming. The tutor's scheduling extension prepares the table before recurring training and investigates preparation failures instead of selecting arbitrary files. [Notes](notes.md#m01-u03--get-and-prepare-data) · [Source](https://learn.microsoft.com/en-us/training/modules/design-machine-learning-model-training-solution/2a-prepare-data)

- **M01-U04 — Select for the broader workflow:** consider model type, training control, time, existing platforms, and language preference. Azure ML supports the ML lifecycle through studio, Python SDK, or CLI; Databricks supports distributed Spark engineering/data science and can integrate with Azure ML; Fabric spans analytics, training, predictions, and Power BI; Foundry Tools supplies prebuilt model APIs, with customization available for some models. Tutor decision rules: investigate applicable prebuilt models before assuming custom training, but evaluate suitability; existing Spark strengthens the Databricks case, while integrated analytics-to-Power BI supports Fabric. **AutoML explores algorithms/parameters; pipelines orchestrate steps.** Their combination is a tutor synthesis, not an executed configuration. [Notes](notes.md#m01-u04--train-the-model) · [Source](https://learn.microsoft.com/en-us/training/modules/design-machine-learning-model-training-solution/3-choose-service-train)

- **M01-U05 — Interface, resource, execution:** studio is the browser interface; workspace is the primary Azure ML resource in a subscription; compute executes jobs. Create or access a workspace—opening studio does not create one. Source starting points: CPU often suits smaller tabular datasets; GPU often suits image/text workloads and can help larger tabular workloads; general-purpose compute balances CPU/memory, while memory-optimized compute suits memory-heavy processing. Monitor training duration and utilization before adjusting. The tutor's synthesis is **AutoML, then evaluate results before deployment approval**, not automatic production readiness. [Notes](notes.md#m01-u05--use-azure-machine-learning-studio) · [Source](https://learn.microsoft.com/en-us/training/modules/design-machine-learning-model-training-solution/3b-use-automated-machine-learning)

- **M01-U06 — Prediction timing and compute:** an endpoint is an address applications call for predictions. Choose real-time when consumers need quick responses; choose batch for collected inputs whose combined results can be saved for later use. Consider scoring frequency, acceptable delay, input quantity, and prediction compute—not just data arrival frequency. Plan serving capacity separately from training resources. Ready real-time capacity has availability cost; batch nodes configured to scale idle capacity to zero can reduce idle node costs, not every associated Azure cost. [Notes](notes.md#m01-u06--integrate-a-model) · [Source](https://learn.microsoft.com/en-us/training/modules/design-machine-learning-model-training-solution/4-decide-between-compute-options)

## Important pitfalls and corrections

- Good sales are not evidence of accurate forecasts. Monitor predictive performance against success criteria. [M01-U01](notes.md#m01-u01--introduction)
- Historical data alone does not imply regression; a future prediction alone does not imply time-series forecasting. Held-out data checks unseen examples, but those examples must also represent the intended population. A population mismatch does not automatically require changing the metric. These distinctions include tutor illustrations/extensions. [M01-U02](notes.md#m01-u02--define-the-problem)
- Predictions for every row prove scoring produced outputs, not predictive quality. High accuracy can hide missed minority positives; a different metric cannot substitute for the required recall or MAE criterion. [M01-U02](notes.md#match-metrics-to-success-criteria)
- Cleaning/removing columns does not necessarily create the required grouped rows. A preparation failure may involve access, copying, or transformation—not necessarily invalid data. A deliberate older validated-data fallback differs from arbitrary-file training. [M01-U03](notes.md#m01-u03--get-and-prepare-data)
- Multiple services support training. Prebuilt models still need evaluation, and a trained artifact does not itself justify production approval. A laptop browser is the interface, not the compute executing the illustrated Azure job; this does not claim every ML workflow must run remotely. [M01-U04](notes.md#m01-u04--train-the-model) · [M01-U05](notes.md#m01-u05--use-azure-machine-learning-studio)
- A large table or a cluster does not make an operation training: applying a saved model is scoring. Low request volume does not remove an immediate-response requirement. ACI/AKS in the source are foundational serving illustrations, **not a verified current deployment recipe**; managed endpoint provisioning was not covered hands-on. [M01-U06](notes.md#m01-u06--integrate-a-model)

Useful tutor-created worked references already in the notes:

- **M01-U02 — Absolute error:** |$240,000 − $260,000| = **$20,000**; MAE averages the absolute errors across examples. Producing prices is scoring; calculating their errors is evaluation. [Worked notes](notes.md#m01-u02--absolute-error-and-mae)
- **M01-U03 — Aggregation:** group valid readings by machine and minute; 18°C, 21°C, 24°C produce one **21°C** mean-temperature row. [Worked notes](notes.md#m01-u03--one-row-per-machine-minute)
- **M01-U06 — Saved model and jobs:** learning parameters and saving a model is training; loading it to predict for 20,000 customers and saving a report file is batch scoring. Saved results remain consumable after scoring nodes stop executing; storage and other costs may remain. [Worked notes](notes.md#saved-model-separate-execution-jobs)
