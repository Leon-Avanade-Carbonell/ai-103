### Ordinary lesson checks

**Tutor-created prompt:** 'Your support agent’s new “friendlier” prompt is committed to Git. It passes review, but after deployment it starts inventing troubleshooting steps. What protection was still missing or ineffective—and how does having the previous prompt version help now?'

**Initial learner response:** 'We will need to have some grounding in the data, such as enforcing RAG and some guardrails for the prompts. Having previous prompt versions allow us to rollback to working versions should there be an issue with the current prompt... LIke a quick restore.'

**Feedback:** Rollback offers a quick recovery target. RAG and guardrails can help, but RAG does not guarantee grounded responses. The tutor supplied effective predeployment testing as the missing or ineffective safeguard and explained that approval alone does not establish technical accuracy. The tutor supplied a worked example testing a known error against approved troubleshooting documentation. The learner did not independently identify testing here.

**Follow-up prompt:** 'Would successfully rolling back to an older prompt prove that the older version is accurate, or would it still need supporting test evidence?' Rephrased: 'In a sentence: does rollback establish quality, or restore a previously selected version?'

**Actual follow-up response:** 'no. not really. it will just be an option to roll-back to. Quality can/will be different each version.'

**Feedback:** Correct distinction between restoring a version and establishing quality; identifying the testing safeguard was scaffolded.
