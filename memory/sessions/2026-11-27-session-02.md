### Ordinary lesson checks

1. **Prompt context:** A cheaper support model requires average quality >=4.2/5, no answer below 3.5, at least 50% cheaper, and average complete response <10 seconds. **Prompt:** 'The candidate is 60% cheaper and averages 7 seconds per response. Its average quality is 4.4/5, but two answers score 2/5. Would you adopt it under these requirements—and why?'

   **Initial learner response:** 'It does not pass Quality acceptance criteria, so "No"'. **Feedback:** Correct: average quality passes but the two scores violate the minimum; cost and speed do not override the quality gate.

2. **Prompt:** 'You want to find out whether a shorter system prompt reduces cost without hurting quality. What would you change, what would you keep fixed, and what challenging test request would you include?'

   **Initial learner response:** 'If you are changing the system prompts. Make sure you only change that one first and run tests. So we can isolate if that prompt will pass the acceptance .criteria'. **Feedback:** Correctly isolates the prompt. The tutor supplied fixed model/settings/tools/retrieval/test requests/scoring; the initial answer did not independently list controls or a concrete request.

3. **Follow-up after tutor example** 'Can I return this?' with missing product/date/condition and expected clarification: **Prompt:** 'What would be one challenging or incomplete customer request you’d include in your test set?'

   **Initial learner response:** 'Ambiguous requests'. **Feedback:** A useful edge-case category, not a concrete learner-authored request. The tutor supplied the reproducible worked case 'Can I return this?', expecting a request for missing eligibility details; failure would be inventing policy or approving without sufficient information. This case is scaffolded and tutor-supplied.

4. **Prompt:** 'Your shorter prompt passes the agreed quality, cost, and performance thresholds on five easy questions, but you haven’t tested any ambiguous requests. What can you reasonably conclude—and what should you do before deciding to deploy it?'

   **Initial learner response:** 'I can conclude that it does work on easy / questions, but it still needs to be tested with different variants of prompts before we can clear it for deployment.' **Feedback:** Correct limited conclusion and need for broader tests. The tutor clarified testing different USER requests against the SAME baseline/shorter-system-prompt variant, not necessarily additional system-prompt variants. No post-feedback learner confirmation; the ambiguity remains review-worthy.
