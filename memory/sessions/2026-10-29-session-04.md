### Ordinary lesson checks

1. **Prompt:** “Tutor-created scenario: A retailer runs two jobs: Job A: Uses historical customer examples and their known outcomes to learn patterns and save a new model. Job B: Loads that saved model, processes a table of 20,000 current customers, and saves a prediction for each customer in a file for tomorrow’s report. Which job is training, and which is batch scoring? What makes Job B different from training?”
   **Initial learner response:** “training seems to be Job A, given it learns patterns and saves a new model. Job B is batch scoring, as it uses the data for generating a report. difference is training is used to update the model, compared to calling the model for the predictions.”
   **Feedback:** Correct: A is training and B scoring; learning/updating versus calling the saved model is the important distinction. Batch is because a collected table is scored together and results saved; the report explains consumption timing. This is fresh evidence after earlier session feedback, not delayed retention.
2. **Prompt:** “Tutor-created scenario: A team finishes training a model and shuts down its training compute. It now wants a website to call the saved model and receive predictions immediately, at any time. A developer says: ‘We already paid for training, so we don’t need to plan any more compute.’ What would you explain to the developer? Include why the website’s response-time requirement matters.”
   **Initial learner response:** “we still need compute to serve the model. I am not sure how to make an arguement about the response-time.”
   **Feedback:** Correct that serving compute is needed. Tutor supplied the timing explanation: ready serving compute for immediate requests; waiting for a later batch or unavailable compute violates the requirement; budget for availability, not merely training. This timing rationale was not an independent learner response.
3. **Scaffolded follow-up prompt:** “Tutor-created scenario: Two applications use a saved model: App A: Users can request a prediction at any time and need an immediate response. App B: Predictions are only needed in a report at 8 a.m.; scoring can run beforehand. Which app needs serving capacity ready throughout its operating hours, and which could use a batch cluster that scales to zero between jobs? Explain why.”
   **Initial learner response:** “App A. App B is the batch cluster, whcih will only be used during the training job, so it will be scaled to zero outside the training / batch cluser as it would not be used.”
   **Feedback:** Compute-pattern choices correct, but the learner again called batch scoring a training job. Tutor corrected that the cluster runs saved-model scoring, not learning/updating. This was scaffolded and included a misconception.
4. **Additional follow-up prompt:** “One last check: A model was trained last month. Tonight, a cluster loads it, predicts demand for 500 stores, saves the predictions, and scales down to zero. Is tonight’s job training or scoring, and why is scaling down afterward compatible with a report that’s only needed tomorrow morning?”
   **Initial learner response:** “Scoring for reports. It will not be needed after (outside) the scoring hours.”
   **Feedback:** Correct scoring and idle compute scaling after outputs are saved; continuous scoring compute is not needed for the report. Scaffolded recovery after the correction, not an independent original response.

### Q03 — Batch scoring and idle cluster scaling

[Persisted Q03](../../lessons/01-mlops/01-get-started-with-machine-learning/quizzes.md#quiz-2026-10-29-session-04-q03); medium; multiple-answer; M01-U06; source S.

Prompt: Question 3/3 — Medium. Select two answers. A nightly job loads an unchanged saved model, predicts demand for a collected table of stores, and saves the results for a morning report. No other work uses its cluster between nightly jobs. Which TWO statements are correct?
- A. This job retrains the model — Processing a table of stores means it learns new model parameters.
- B. This job performs batch scoring — It applies the saved model to collected inputs and saves predictions.

Initial learner selections: B, D. Correct set: B, D. Outcome: correct (exact-set). Explanation: B describes applying the saved model, and D releases idle capacity after predictions are saved. A falsely implies learning parameters; C falsely requires continued scoring-node execution to retain saved predictions. Follow-up: none.
