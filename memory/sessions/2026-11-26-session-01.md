### Q01 — OIDC authentication

[Quiz item](../../lessons/01-mlops/07-deploy-and-monitor-models/quizzes.md#quiz-2026-11-26-session-01-q01); M07-U05; easy; single-answer; S1, control separation S2.

**Prompt:** What is the main authentication benefit of OIDC in this deployment workflow? Select one answer.
- A. Automatic production approval — Approve releases when Azure login succeeds.
- B. Short-lived federated access — Authenticate without storing a long-lived Azure client secret.

- D. Unrestricted Azure permissions — Give the workflow access to all Azure resources.

Initial selection B; key B; correct. **Explanation:** OIDC provides short-lived federated authentication without a stored client secret. It does not approve releases (A), validate predictions (C), or grant unrestricted permissions (D); S1, with control separation in S2. Follow-up: no retry.

### Q02 — Isolated direct testing

[Quiz item](../../lessons/01-mlops/07-deploy-and-monitor-models/quizzes.md#quiz-2026-11-26-session-01-q02); M07-U05; medium; single-answer; S1.

**Prompt:** Green is ready at 0% routed traffic. You want to test it without returning green's predictions to normally routed users. Which action fits? Select one answer.
- A. Route 10% to green — Use a limited live traffic split.
- B. Route 100% to green — Test after full promotion.
- C. Invoke the registered model asset — Use registration alone as the prediction service.
- D. Invoke green directly — Specify --deployment-name green in the endpoint invocation.

Initial selection D; key D; correct. **Explanation:** Direct invocation targets green while normal routing remains unchanged. A and B expose normally routed users to green; C confuses a registered asset with a serving deployment (S1). Follow-up: no retry.
