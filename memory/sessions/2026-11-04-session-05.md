### Ordinary lesson check

**Prompt:** “Your team wants to retrain the same model weekly on updated data and compare the results with previous weeks. What roles would the training script/command job and MLflow each play?”

**Actual initial response:** “training script will perform the model training. the command job will trigger when this training happens. And the MLflow will log what is happening in the model/job/training.”

**Feedback:** Mostly right: the script performs processing and training. The command job defines/runs the script with inputs, environment and compute; it does not itself define a weekly trigger. A scheduler/automation submits the job. Configured MLflow logging captures parameters, metrics and artifacts, not automatically everything. The tutor supplied: weekly automation → submits command job → runs training script → MLflow records results.

**Follow-up prompt:** “if you submit a command job manually today, does it automatically run again next week? Why or why not?”

**Actual response:** “no. I think you will have something like a cron-job that will trigger the script.”

**Feedback:** Correct about recurrence; in this workflow a cron-like scheduler should submit the command job, rather than necessarily execute the script directly. This was post-feedback scaffolded recovery, not independent scheduler API knowledge or execution.
