## Topics discussed

GenAIOps builds on DevOps/MLOps and manages pretrained models, prompts, agents and connectors; evaluation includes groundedness, coherence, safety and cost. Explore defines needs and design; Build develops and evaluates; Operationalize deploys and delivers reliable, responsible service. Feedback loops are nonlinear; management governs security, governance and compliance throughout. Tutor-created conceptual applications covered regression diagnosis before prompt edits, outdated RAG policy versus grounded answers, production rollback and permissions from architecture onward. ### Ordinary lesson checks

1. **Prompt:** “Tutor-created scenario: Your IT-support agent is already in production. After an update, it starts giving incorrect access-policy advice, although its responses are still fast and friendly. Which loop would you return to first, and what would you investigate there?”

   **Initial learner response:** “I will have to look at the explore to change the prompts again.”

   **Feedback:** Explore is valid for prompt or architecture redesign, but do not assume prompts caused the issue. Build usually comes first to reproduce and evaluate changes to prompts, retrieval or context use; Explore handles deeper design and Operationalize handles live risk, such as rollback. Initial reasoning was partial; the diagnostic sequence was tutor-supplied.

2. **Follow-up prompt:** “You discover that retrieval supplied an outdated policy document, and the agent answered faithfully from it. What would you change first, and how would you check that the change worked before releasing it?”

   **Learner response:** “I will check the build for the RAG reference of the policy document”.

   **Feedback:** Correct Build/RAG investigation after the prior explanation, but the release-test part was omitted. Tutor explained checking approved-source freshness and an older indexed copy, then fixing the source or indexing. Scaffolded transfer; no fix executed.

3. **Prompt:** “Before releasing that fix, what test would convince you that the agent now uses the current policy correctly?”

   **Initial learner response:** “I will try to run a groundedness test to see if it using the current policy”.

   **Feedback:** Groundedness is relevant, but an answer can be grounded in outdated context. Tutor supplied two checks: confirm the retrieved version is current and approved, and confirm the answer faithfully follows the passage with expected guidance. No independent retry of the freshness distinction and no test run.

4. **Prompt:** “The team proposes: ‘We’ll check permissions, security, and compliance only just before deployment.’ Is that sufficient? Which lifecycle loop covers those concerns, and when should it apply?”

   **Initial learner response:** “Operationalize loop; only after the tests (evaluations) passed with saftey and quality.”

   **Feedback:** Release evaluations matter, but the overarching management loop governs security, governance and compliance throughout Explore, Build and Operationalize. Tutor examples covered designing, implementing/testing and monitoring access; a grounded answer can still be unauthorized.

5. **Scaffolded retry prompt:** “During Explore, the team wants to connect the agent to confidential HR documents. Should permission requirements be decided now or only after evaluation passes—and which loop governs that decision?”

   **Learner response:** “It should be decided from the start as a requirement. As part of the architecture, so we can implement the correct governance.”

   **Feedback:** Correctly applies requirements from the start of design, under management, with implementation, testing and maintenance across the lifecycle. The learner did not explicitly name management; this recovery followed correction and is not independent initial mastery.
