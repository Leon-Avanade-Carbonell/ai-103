2. **Prompt:** “An AutoML experiment ranks models by accuracy: A 94% accuracy, 180 ms latency; B 93%, 40 ms. Your application requires predictions in under 100 ms. Which model ranks first in AutoML, and which would you investigate as the deployment candidate? Why?”
   - **Initial learner response:** “B ranks first because of the latency. Accuracy might be lower, but it is within the requirements.”
   - **Feedback:** B is a sensible latency candidate, but A ranks first by the primary metric, accuracy. No minimum accuracy was specified, so B still needs validation. The separation of ranking and deployment suitability was tutor-supplied.
3. **Follow-up prompt:** “If we keep accuracy as the primary metric, but tighten the application’s latency limit to under 30 ms, does AutoML’s first-place model change—and does either candidate meet the latency requirement?”
   - **Learner response:** “No to AutoML's first place. Because the primary metric is still Accuracy. The latency change will mean that both models are suitable for deployment.”
   - **Feedback:** Ranking was correct but eligibility was reversed: neither 180 nor 40 ms is below 30. A tighter requirement excludes candidates; it does not speed up models. Tutor supplied this correction.
4. **Follow-up prompt:** “Keeping the same models and accuracy ranking, suppose the latency requirement becomes under 50 ms. Which model ranks first, and which meets the latency requirement?”
   - **Learner response:** “Oh, I misunderstood the meaning of 'tightening'. I thought it was addressing model A's latency. As for your new question, A still ranks first. Only B is fulfilling the latency requirement.”
