### Ordinary lesson checks — M05-U02

**1. Prompt:** “You want another team to reuse your training script. You share only train.py, which imports scikit-learn and expects a data path. What information is still missing to make this a ready-to-use component? Explain using the three parts above; no code is needed.”

**Actual initial answer:** “we would need the metadata, and interface information, as well as the command and environment dependencies.”

**Feedback:** Correct. The script provides code; name/version, declared data/model ports, invocation and runtime are still required. The question was prompted after teaching the three categories; those details were tutor-supplied, not all independently enumerated by the learner.

**2. Prompt:** “You are building a pipeline from local code, and no other team needs the component yet. Must you register it first, or can you use the loaded local component directly? What changes when another team needs workspace-based reuse?”

**Actual initial answer:** “you can run it as a script, but not a component directly unless you register it as a component.”

**Feedback:** Incorrect. Registration is optional for local pipeline use; loading creates a definition, pipeline submission executes, and registration publishes a workspace asset. The tutor supplied this corrected comparison.

**Follow-up prompt:** “You have train.py and a valid train.yml. You load the YAML, add the component to a pipeline, and submit the pipeline job—without calling create_or_update. Can the training step run, and what would registration add?”

**Actual follow-up answer:** “yes, you can run it as a local compoent, registration allows it to be published as a resuable component for a team.”

**Feedback:** Correct with the specified pipeline-submission execution context. This is scaffolded recovery after the tutor's correction, not untouched independent mastery or actual execution.

**3. Prompt after showing YAML:** “If you rename the YAML input from training_data to raw_data, what must change in the command? Must the script’s --data argument also be renamed?”

**Actual initial answer:** “${{inputs.raw_data}} must accept --raw_data”

**Feedback:** The YAML reference is right, but the script flag need not change. The tutor showed `python train.py --data ${{inputs.raw_data}}` and explained the port name versus parser flag distinction.

**Follow-up prompt:** “A script accepts --learning-rate, while the YAML declares an input named lr. What command fragment connects them?”

**Actual follow-up answer:** “--learning-rate ${{inputs.lr}}”

**Feedback:** Correct transfer to a new name pair after scaffolding; this is not practical execution evidence.
