### Ordinary lesson checks

**1. Prompt:** 'Two deployed hiking-agent versions produce different recommendations. Their prompt files are identical. What two other parts of the agent would you inspect before concluding that prompt version control has failed?'

**Initial response:** 'I will look at the tools and the model selected.'

**Feedback:** Correct: tools and model. The tutor additionally explained individual response variation even with identical configurations. Independent evidence for identifying non-prompt components.

**2. Prompt:** 'Version B gives friendlier, more personalized answers than version A. Before promoting B, how would you compare the two versions, and what finding would make you hold back the release?'

**Initial response:** 'I will try different versions of the prompt requesta against those models and see what the score is. Basically check the quality and safety. If the score drops or safety and guardrails scores fail, we should stip the build.'

**Feedback:** Correct quality/safety gate. Tutor supplied the refinement: use the same requests across versions, hold model/tools/conditions consistent to isolate a prompt change, predefine acceptance thresholds, and do not let aggregate improvement override a required safety failure. No independent post-feedback controlled-comparison answer was obtained.

**3. Prompt:** 'Your team includes nontechnical reviewers who approve prompt wording. Which storage approach would you choose, and why?'

**Initial response:** 'Maybe in Github? The prompts should be stored in the prompt library, but has to be tested/checked beforehand.'

**Feedback:** GitHub is a location, not a storage format. Tutor suggested separate .txt/.md files in a prompts/ folder for clear wording review and distinguished storing proposed edits from release gates.

**4. Scaffolded follow-up prompt:** 'What advantage does a separate prompt file give those reviewers compared with embedding the prompt inside a Python deployment script?'

**Response:** 'It will be for those non-technical people. They might not have the proper access and/or capability to work with GitHub. We can separate the concerns of the prompts and the deployment scripts. the prompt library can keep track of the prompts'

**Feedback:** Separation of concerns is correct, but separate files do not fix GitHub permissions or workflow capability; a library organizes prompts and Git provides committed history. This was scaffolded, not an independent storage choice. No further permission-clarification answer was obtained.
