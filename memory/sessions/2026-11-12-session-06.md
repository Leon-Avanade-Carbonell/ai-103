**Full prompt:** A teammate changes your data-preparation script. Training still finishes successfully, but the model performs much worse. Why would a workflow that checks only “the training job succeeded” be insufficient, and what additional check would you want?

**Initial learner response, verbatim:** “Because the job might have completed by has the results go down. I might have a check of the primary metric and try to compare it with previous runs.”

**Feedback given:** “Exactly. Successful execution is not the same as acceptable model quality. Checking the primary metric against a defined acceptance threshold—and comparing it with a previous accepted model—can catch regressions. One useful distinction: compare runs under comparable evaluation conditions. A changed evaluation dataset can make the metric difference harder to interpret. That demonstrates the introduction’s core idea: automate both the training process and meaningful validation, while retaining traceability to the code change.”
