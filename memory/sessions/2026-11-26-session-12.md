### Ordinary lesson checks

**1. Prompt:** A teammate says: “My prompt change is on a feature branch, so it’s safe to run the deployment script. It still targets our production agent, but I haven’t merged anything.” Would you let them run it? What would you change first, and why?

**Initial learner response:** 'No. It should target the development agent. No environment drifts.'

**Feedback:** Correct target decision. The immediate risk is a premature production change; drift specifically means divergence from the approved recorded configuration. An unreviewed deployment could cause both. No follow-up answer.

**2. Prompt:** Your candidate passes all required tests and receives PR approval. The team merges and tags the release, but production still uses the old prompt. What step is missing, and what would you check to confirm the intended version actually reached production?

**Initial learner response:** 'deployment (CI/CD). It might have failed evaluation. Check logs.'

**Feedback:** Correctly identifies deployment and relevant logs. Evaluation failure is possible, not established; the workflow might not have triggered, authentication might have failed, or the target might be wrong. Tutor supplied checking deployment-step success, revision and target, and verifying that the live agent configuration/version maps to the approved release. No follow-up answer. Earlier [session-11 ordinary traceability check](2026-11-26-session-11.md#ordinary-lesson-checks) and [Q04](../../lessons/02-genaiops/02-prompt-management-and-versioning/quizzes.md#quiz-2026-11-26-session-11-q04) provide prior independent identification/recognition of a deployed-version mapping; they are not a current-session answer to this prompt.

**3. Prompt:** After deployment, a support agent’s rate of unsupported troubleshooting advice rises above the release threshold. The previous approved configuration is still available. What would you do immediately, and why would simply reverting the prompt file in Git be insufficient?

**Initial learner response:** 'Perform a rollback while investigating the failed deployment. If running blue-green, route traffic to blue.'

**Feedback:** Rollback is appropriate. Routing back to blue is valid only if separately deployed agent configurations and application routing exist; this unit does not establish a built-in Foundry blue/green capability. A deployment can succeed technically while behavior regresses: investigate the production regression, not necessarily a failed deployment. Tutor supplied why a Git-only revert does not restore live configuration. No follow-up answer; do not infer an independent answer to the second half.
