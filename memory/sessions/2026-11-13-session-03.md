**Check 1 prompt:** “A GitHub Actions workflow needs to submit training jobs to one Azure ML workspace. You have: The workspace name; A service principal’s client secret; An Azure role assignment for that service principal. Where would you store the workspace name and client secret, and would you scope the role to the workspace or the whole subscription? Why?”

**Initial response, verbatim:** “I will pyt them in the Github secrets with just the workspace scope. Because of the rule of limited access.”

**Feedback:** Workspace scope follows least privilege assuming it covers required operations; put the client secret in secrets and the non-sensitive workspace name in variables. Storing the name as a secret is not inherently unsafe, but unnecessary. The narrow scope rationale was independent; the storage distinction required tutor correction.

**Check 2 prompt, after teaching OIDC:** “Tutor scenario: you replace client-secret authentication with OIDC, but the identity has no Azure role allowing job submission. Would authentication alone let the workflow submit the training job? Why or why not?”

**Initial response, verbatim:** “I believe so, given GitHub will issue the short-lived OIDC token.”

**Feedback:** Not quite: the token proves identity, not permission. Authentication may succeed while submission is denied without a suitable role. Tutor used a badge/doors analogy; OIDC does not grant permissions.

**Follow-up:** Learner agreed to retry: “sure”. After feedback, the scaffolded prompt was: “A workflow successfully signs in to Azure using OIDC, but submitting an Azure ML job returns an authorization error. Would you first investigate: A. The identity’s Azure role assignment and its scope B. Creating a long-lived client secret to replace OIDC Which would you choose, and why?”

**Follow-up response, verbatim:** “A”. **Feedback:** Correct selection: sign-in succeeded, so inspect role and scope; a client secret cannot fix missing permissions. No explanation was provided despite the why request. This is scaffolded recognition, not independent demonstrated reasoning. The final Git tracking topic was tutor-explained without a learner check.
