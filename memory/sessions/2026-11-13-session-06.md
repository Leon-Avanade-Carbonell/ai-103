### [Q01 — Endpoint choice](../../lessons/01-mlops/07-deploy-and-monitor-models/quizzes.md#quiz-2026-11-13-session-06-q01)

Medium; single-answer; M07-U02; S1. **Prompt:** An appointment-booking application must display a no-show risk prediction immediately after each booking. Which deployment approach fits this requirement? Select one answer.

- A. Scheduled batch endpoint — Collect records and score them in a periodic job.
- B. Managed online endpoint — Return a prediction synchronously for each request.
- C. Registered model only — Store the model as a versioned workspace asset.

**Initial selection:** B. Managed online endpoint. **Correct set:** B. **Outcome:** correct. **Explanation:** Online serving meets the synchronous-response requirement. Periodic batch scoring does not, and registration stores an asset rather than serving it (S1). **Follow-up:** No retry.

### [Q02 — MLflow no-code deployment](../../lessons/01-mlops/07-deploy-and-monitor-models/quizzes.md#quiz-2026-11-13-session-06-q02)

Medium; single-answer; M07-U02; S1. **Prompt:** A team has a supported MLflow model and wants Azure Machine Learning no-code deployment. What does Azure Machine Learning generate from the model’s MLflow metadata? Select one answer.

- A. A new training dataset — Data for the next retraining run.
- B. Production approval rules — Controls for approving deployment releases.
- C. Scoring script and environment — The inference code and runtime environment.
- D. A retraining schedule — A recurring schedule for updating the model.

**Initial selection:** C. Scoring script and environment. **Correct set:** C. **Outcome:** correct. **Explanation:** MLflow metadata supports generation of inference code and environment, not training data, approval rules, or a retraining schedule (S1). **Follow-up:** No retry.

### [Q03 — Registered model lifecycle](../../lessons/01-mlops/07-deploy-and-monitor-models/quizzes.md#quiz-2026-11-13-session-06-q03)

Medium; multiple-answer; M07-U02; S1. **Prompt:** A team manages registered model versions in Azure Machine Learning. Which two actions follow the lifecycle rules described in this unit? Select two answers.

- A. Update an existing version’s tags — Change descriptive metadata without changing its artifact.
- B. Replace an existing version’s artifact — Keep the same version number after retraining.
- C. Archive a version to delete it — Remove the artifact so workflows cannot reference it.
- D. Register a changed artifact as a new version — Give the retrained model its own version.

**Initial selections:** A. Update an existing version’s tags; D. Register a changed artifact as a new version. **Correct set:** A, D. **Outcome:** correct, exact match. **Explanation:** Tags/descriptions can change on an existing version; changed artifacts require new versions. Replacing the artifact violates that rule, and archiving is not deletion (S1). **Follow-up:** No retry.

### [Q04 — Repeatability versus predictive quality](../../lessons/01-mlops/07-deploy-and-monitor-models/quizzes.md#quiz-2026-11-13-session-06-q04)

Easy; single-answer; M07-U02; S1. **Prompt:** Why does the unit recommend automating registration, deployment, and testing when a model is regularly retrained? Select one answer.

- A. To avoid registering model versions — Deploy without keeping versioned assets.
- B. To make repeated releases less error-prone — Replace recurring manual steps with a repeatable pipeline.
- C. To guarantee prediction accuracy — Ensure every retrained model is accurate in production.
- D. To remove the need for testing — Treat successful registration as sufficient validation.

**Initial selection:** C. To guarantee prediction accuracy. **Correct set:** B. **Outcome:** incorrect. **Explanation:** The source motivates automation by slow, error-prone manual releases. Tutor feedback clarified that process repeatability does not guarantee predictive quality. Automation retains registration and testing rather than eliminating them (S1); a pipeline can reliably deploy a poor model. **Follow-up:** Tutor supplied the distinction; no learner response or recovery check after feedback.

**Strengths and gap:** endpoint choice, supported no-code inference packaging and lifecycle rules; Q04 confuses release-process reliability with predictive quality. Feedback is not independent recovery.
