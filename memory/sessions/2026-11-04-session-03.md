## Topics discussed

An experiment groups runs at a tracking destination; `set_experiment` and `start_run` do not train. Enable supported-framework autologging before training; integration-selected parameters, metrics, artifacts and models can be complemented with custom logs. `log_param` records settings, `log_metric` records supplied numeric results, and `log_artifact` attaches an existing file; logging does not measure latency or create that file.

### Q04 — Recording versus measuring

[Persisted Q04](../../lessons/01-mlops/02-experiment-with-azure-machine-learning/quizzes.md#quiz-2026-11-04-session-03-q04); medium, single-answer.

**Prompt:** Your code calls mlflow.log_metric("prediction_latency_ms", 42.0). What does this call establish? Select one answer.
- A. MLflow measured latency — The call timed model predictions.
- B. MLflow trained a faster model — The call optimized model latency.
- C. The supplied value was recorded — The call logs 42.0; measurement happens elsewhere.
- D. A report file was created — The call writes a validation report artifact.

**Initial selection:** A. MLflow measured latency. **Key:** {C}. **Outcome:** incorrect. **Explanation:** C is correct: `log_metric` records the supplied value. It does not time predictions (A), optimize a model (B), or create a report file (D). Source includes studied tutor clarification. **Follow-up:** tutor explained logging as writing a measurement into a record, not taking the measurement; timing code must produce the value first.
