**Initial learner answer, verbatim:** “train.py would be in Github, 20-GB would be in a Data Lake Storage, Access credential would be in Azure Key Vault, and a trained model pick would be in the Azure ML job model assets.”

**Feedback:** All placements appropriate; tutor clarified that registered named/versioned model assets differ from job outputs. The learner did not initially answer why traceability matters. The tutor supplied the explanation: identify producing code/configuration, investigate regressions and recover an earlier recipe.

**Check 2 prompt:** If you revert to that Git commit, is it enough to reproduce the model—or what else would you need to identify?

**Initial learner answer, verbatim:** “No, the git commit includes the linked model. the model itself stays in the Azure ML job model assets.”

**Feedback:** The learner recognized external artifact storage, but misunderstood automatic Git model links and terminology. Tutor explained that a commit identifies code/configuration but does not automatically include a model link; job/model metadata can record the commit; registered assets differ from retained outputs. Data version, environment and settings are also needed for reproduction, and randomness can matter. This enumeration and linkage explanation were tutor-supplied, not independently produced.

**Follow-up prompt:** Small scenario: You restore the original Git commit, but your training script reads a dataset that has since changed. Would you expect it to reproduce the original model? Why or why not?

**Learner answer, verbatim:** “No, because the model and dataset you had would generate a different output.”

**Feedback:** Correct changed-data conclusion, with wording clarification: training consumes code/data/environment/settings to produce a model; the previous model is not an ordinary input unless resuming or fine-tuning. This is a scaffolded recovery, not flawless initial understanding.

### [Q01 — Training recipe](../../lessons/01-mlops/06-automate-training-with-github-actions/quizzes.md#quiz-2026-11-12-session-07-q01)

Easy; single-answer. **Prompt:** Where should a training script and its dependency definition normally be versioned? Select one answer.
- A. Azure Key Vault — Store both as secret values.
- B. Git repository — Version both as part of the training recipe.
- C. Azure ML model assets — Register both as trained models.
- D. Training job logs — Keep both only as execution logs.

Initial: B. Git repository. Key: B. Outcome: correct. Explanation: Scripts and dependency definitions describe the training recipe and belong in Git. Key Vault holds secrets, model assets hold trained models, and job logs record execution rather than replace source control. Follow-up: none.

### [Q02 — Assets outside Git](../../lessons/01-mlops/06-automate-training-with-github-actions/quizzes.md#quiz-2026-11-12-session-07-q02)

Medium; multiple-answer. **Prompt:** Which two files should normally stay OUT of your Git repository? Select two answers.
- A. Component definition YAML — Defines a pipeline component.
- B. requirements.txt — Lists Python dependencies.
- C. Raw 20-GB training dataset — Contains the training records.
- D. Azure access credential — Grants access to Azure resources.

Initial: C. Raw 20-GB training dataset; D. Azure access credential. Key: C, D. Outcome: correct, exact match. Explanation: Store the dataset in a suitable data service and the credential in a secret store. Component YAML and dependency files belong in Git. Follow-up: none.

### [Q03 — Model registration](../../lessons/01-mlops/06-automate-training-with-github-actions/quizzes.md#quiz-2026-11-12-session-07-q03)

Medium; single-answer. **Prompt:** Training produces model.pkl. Your team wants to manage it as a named, versioned model for later use. What should you do? Select one answer.
- A. Commit the binary to Git — Manage it alongside training scripts.
- B. Store it in Key Vault — Manage it as a secret.
- C. Keep only a log message — Record that training finished.
- D. Register an Azure ML model asset — Manage the trained artifact by name and version.

Initial: D. Register an Azure ML model asset. Key: D. Outcome: correct. Explanation: Registration provides named, versioned model management. A job may retain the original output, distinct from registration. Git is for the recipe, Key Vault for secrets, and a log message cannot replace the artifact. Follow-up: none.

### [Q04 — Commit traceability](../../lessons/01-mlops/06-automate-training-with-github-actions/quizzes.md#quiz-2026-11-12-session-07-q04)

Medium; single-answer. **Prompt:** A model's performance regresses after a preprocessing change. Why is recording the producing Git commit useful? Select one answer.
- A. It identifies the code change to inspect — Review the producing recipe and compare it with an earlier commit.
- B. It contains the dataset automatically — Recover all training records from the commit.
- C. It guarantees acceptable model quality — A recorded commit establishes model accuracy.
- D. It replaces model registration — No separate trained artifact needs to be retained.

Initial: A. It identifies the code change to inspect. Key: A. Outcome: correct. Explanation: The commit lets you inspect and compare the producing code. It does not automatically contain the dataset, certify model quality, or replace storing and registering the model. Follow-up: none.

### [Q05 — Data version and reproducibility](../../lessons/01-mlops/06-automate-training-with-github-actions/quizzes.md#quiz-2026-11-12-session-07-q05)

Medium; single-answer. **Prompt:** You restore the original training code, dependency definitions, and settings, but train on a newer dataset. Which conclusion is justified? Select one answer.
- A. The original model is guaranteed — An unchanged Git commit fixes every training input.
- B. Training now requires the old model as input — Every training run starts from a registered model.
- C. The model may differ because the data changed — Reproducing a run also requires identifying its data version.
- D. Git should store the credential instead — Credential storage determines the model's learned behavior.

Initial: C. The model may differ because the data changed. Key: C. Outcome: correct. Explanation: A changed dataset can change the trained model. The commit does not fix every input, ordinary training need not start from an old model, and credentials control access rather than learned behavior. Follow-up: none.
